# Backend operations

Apply the versioned SQL migrations in filename order with the Supabase CLI (`supabase db push`) or the project's deployment migration step. Use a dedicated project and keep `SUPABASE_SERVICE_ROLE_KEY` on the server. No Prisma is used. All public tables enable RLS, explicit deny policies block anonymous/authenticated users, and operational RPC execution is restricted to `service_role`. Admin actions must authenticate before calling these server services.

`runNewsSync()` runs in the Node runtime, using a durable PostgreSQL lease, 5-minute scheduled idempotency keys, fenced transactional item commits, and a default 240-second work budget. The protected cron route should have a 300-second runtime allowance. Schedule that route using the hosting scheduler and the configured cron secret; SQL migrations do not install a separate hidden scheduler. `runNewsSync({sourceId})` uses the same global lease for an explicitly requested enabled source. Missed work resumes on later runs; a source is not marked checked when the time budget interrupts its item list. After three extraction failures for the same source URL/hash, that version is skipped; operators can inspect `source_items.last_error` and explicitly reset its attempts after fixing the issue.

Sources must be configured by an authenticated administrator. All auto-publication switches default to false. RSS, Atom, JSON normalized `{items:[{id,url,title,content,publishedAt,modifiedAt}]}` (or an array), channel-specific YouTube Atom feeds, and explicitly opted-in HTML `<article>` elements are supported. HTML does not execute JavaScript or recursively crawl. Sources are limited to 50 entries/fetch and 40,000 characters/item, with HTTPS-only exact host allowlists, public-only DNS answers, checked-address pinning, redirect revalidation, byte limits, deadlines and bounded retry. Compressed responses are rejected to avoid decompression bombs. A source with no usable article text must be fixed or replaced by an attributable feed/API.

No enabled live publisher or invented RSS URL is installed by these migrations. A working official Rockstar Newswire feed/API has **not** been verified in this environment; its JavaScript homepage does not establish an ingestible article feed. The official VI site links the Rockstar YouTube handle, but an exact channel ID and feed ownership have not been verified here. YouTube ingestion is therefore available as reported media, while automatic official YouTube promotion remains unsupported. Do not enter a guessed feed, channel ID, or fabricated current article. Official authority is restricted to the exact reviewed hosts in `src/services/trust.ts` and matching SQL checks; all other sources retain their configured lower trust.

Cheap GTA relevance checks and exact URL/hash/title duplicate attachment run before AI. Same-URL corrections, ambiguous matches and higher-authority evidence require extraction. Structured Responses output is validated with strict Zod, checked against supplied source evidence, then cached by content hash + model + schema version for seven days. Trust/status are enforced independently in code and PostgreSQL. The model cannot choose a source URL or declare confirmation. Evidence retained with an attachment is bounded to five short quotes (1,200 characters total). Unsupported numeric claims and ambiguities require review; source-number presence is not proof of semantic correctness. All summaries still need editorial judgment. Full source bodies are not stored by ingestion. Token counts and cache hits are recorded in `automation_logs`; cache expiry does not substitute for semantic validation.

Weekly data requires explicit grounded date boundaries and per-field evidence. Multipliers must match the same activity and currency clause; ambiguous boundaries are rejected. `event_end` is exclusive. Active public reads require a confirmed published weekly row and a published parent article, and check the event window at read time even if cron is down. Moving an article to draft/review/archive removes linked public weekly visibility. Republishing an article does **not** automatically approve its weekly data: review and publish that row separately. Expiration and view increments do not revalidate historical source enablement or alter editorial timestamps.

`npm run seed` requires `ALLOW_FICTIONAL_SEED=true` and loads only explicitly named, historical `[FICTIONAL TEST]` records. It never sets up real sources, release dates, payouts or rewards. Production public reads always exclude these records, including when `DEMO_MODE=true`. Development permits fixtures; other nonproduction environments require explicit demo mode. Seed re-runs upsert only their stable fixture IDs.

Run `npx vitest run tests/backend` to test the adapters, SSRF boundary, extraction, coordinator, and real PostgreSQL migrations/RPCs with PGlite. This exercises database behavior without Docker, but it is not a live hosted-Supabase/OpenAI connectivity test. Real credentials, verified feeds and an actual scheduler still need a deployment smoke test. Periodically purge expired `ai_extractions` and aged operational logs according to the desired retention policy; public cache expiry is cleaned by cron. Analytics tables and their RPCs are maintained in migration `202609100010_analytics.sql` by the main application agent.
